# 学习架构整理

## 范围

按已确认的渐进式方案，先整理学习存储和流程模块。保留现有界面、题型、测评、生成顺序、闯关解锁、提交锁定、复测与归档规则。本次不更换框架、不接云端、不修改提示词或模型。

## 模块职责

- `services/learning.ts`：页面使用的公开接口、创建对话与手动编辑记忆。
- `learning-repository.ts`：旧版迁移、目录、独立课程状态、消息分页、长期记忆和版本检查。
- `learning-runtime.ts`：同课互斥、结构化 AI 请求、上下文组装及消息追加。
- `learning-generation.ts`：文章与配套题目分步生成、章节发布、闯关解锁试卷。
- `learning-conversation.ts`：测评与错题复测、回答批改和用户补充分类。
- `learning-exam.ts`：试卷提交快照、整卷批改、独立试卷批改。
- `learning-archive.ts`：归档总结队列、记忆版本检查、失败重试。
- `learning-aside.ts`：临时随时问，读取 UI 对话上下文，不写学习记录或记忆。
- `core/learning-flow.ts`：合法阶段转换及试卷生成计划常量。
- `local-storage.ts`：底层键值存储、缓存清理、可恢复多键事务。

## 存储协议

原 `learning_v1` 仅作为旧版迁移与备份兼容入口。新数据分为：

| 键 | 内容 |
| --- | --- |
| `learning_v2_index` | 对话 ID、标题、类型、阶段、课号、完成校验结果及记忆错误 |
| `learning_v2_session_<id>` | 一课的题目、作答、证据、版本、消息数量等状态，不含消息数组 |
| `learning_v2_messages_<id>_<page>` | 每页最多 20 条原始 UI 消息，含解析和通知 |
| `learning_v2_memory` | Markdown 长期记忆及归档对话 ID、版本、更新时间 |

页面只读取目录、当前课程状态和足够填满显示窗口的消息页。系统通知继续隐藏；分页读取按可见消息计算窗口。AI 业务操作可读取当前对话完整消息，但不再读取其他课程的历史。保存时比较消息页，只写实际变动的页；禁止用未加载完整消息的状态覆盖历史。

全量 `load()` 保留用于备份及测试兼容，不再用于常规页面刷新。内部备份功能仍导出原来的逻辑格式，恢复时清除旧的 v2 键后按需迁移；界面不会恢复已移除的备份按钮。

## 迁移和恢复

先标准化旧流程和旧记忆，再一次事务写入拆分记录，最后删除旧键。写入失败会恢复旧数据，下次读取可重试迁移。不会直接修改用户当前设备上的真实存储；更新后的程序第一次读取时迁移。

多键事务先写 `storage_transaction_pending`，记录各键原值及原先是否存在；然后执行写入，最后删除恢复记录作为完成标记。进程在完成标记前退出，下次正常读写先回滚。回滚失败则保留记录并阻止继续读取半写入状态。

这仍依赖单次微信存储操作的可靠性，不是数据库级事务；磁盘损坏、系统清除数据不在恢复范围内。事务和首次迁移需要额外空间；空间不足时保留原数据并报告失败。

## 流程规则

测评：介绍 → 测评 → 归档。

课程：生成文章 → 生成配套题 → 阅读闯关 → 答卷 → 批改 → 补学复测 → 完成。全对试卷可从批改直接完成。

所有正常业务阶段转换通过 `transition`，禁止跨类型、倒退或跳步。题目数量、闯关是否完成、答案是否提交、复测是否达标仍由对应业务函数验证。旧版阶段修复仅允许在迁移入口进行。

保留分步生成断点、提交时答案快照、批改后保存再出下一题、记忆归档队列及版本检查，避免重试重新批改或覆盖手动编辑。

## 验证与后续边界

测试覆盖：旧数据迁移失败/重试、记录和记忆完整保留、分页不读取无关历史、增量写入、版本冲突、事务中断恢复、回滚失败恢复、合法状态转换，以及原有完整学习流程。

本次不包含 AI 请求层合并、上下文总预算、阅读页交互拆分或云同步。消息分页减少存储与渲染开销，但当前课的题目、回答证据仍按课保存；极长单课、极多目录项可以在实际数据支持下进一步拆分。
