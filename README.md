# 英语精读

原生微信小程序，使用 TypeScript（strict），围绕文章阅读、单词闯关与 AI 学习课程展开。

**项目处于测试阶段。** 数据结构可能调整，必要时可以清空测试数据，不承诺旧测试数据的跨版本兼容。正常学习中的作答保存、失败重试和中断恢复仍需保证可靠。

## 功能

- **书架与阅读**：内置读物、自建章节、连续向上/向下加载文章；按原文段落排版，支持主题、字体、字号、行距与缩进设置。
- **选词与笔记**：双击选词、长按选句，支持翻译、拆解、提问和笔记。翻译单词时自动加入生词本；笔记通过气泡入口查看，长按编辑或删除。
- **互动试卷**：阅读理解、完型填空、英译汉和汉译英，支持材料与题目混排、选择题和文本输入。草稿自动保存，提交后包括空答在内的全部答案锁定，批改后显示结果与解析。
- **学习历史**：侧边栏切换对话，向上滚动加载更早消息。
- **悬浮答疑**：可拖动并自动靠边，支持流式输出和常用 Markdown 格式，包括标题、加粗、列表、引用、代码块和表格。

## AI 学习流程

首次使用先介绍英语基础、目标和时间安排，再进行 24 题水平测评。测评结束后保留只读历史，并生成归档记忆。

```text
生成文章与配套题目 → 阅读与单词闯关 → 解锁试卷
→ 提交并批改 → 错题补学与新题复测 → 完成本课并归档
```

- 「AI 学习」书籍初始为空，由 AI 生成课程内容。
- 文章和配套题目按步骤生成，失败可从当前步骤重试。
- 标准试卷包含阅读理解 5 题、完型填空 10 题、英汉互译 4 题。
- 完成单词闯关前，配套题目不会发布到阅读页面；解锁后通过所属文章右侧的「试卷」按钮进入。
- 每个错题知识点至少答对一道新出的同类题，才算补学通过。整卷全对可直接完成课程。
- 当前课程完成且归档记忆更新成功后，才能主动开启下一课；每第三课作为复习课。

### 记忆与临时提问

**短期记忆**按对话隔离，包含题目、用户回答、对错及有效补充。主学习流程不反复传入 AI 解析；补充内容先分类为疑问、后续要求或无关内容，后续出题参考有效要求。

**长期记忆**在对话完成归档时总结并合并为 Markdown，记录用户背景、目标、偏好和学习经历，不逐题更新，也不维护固定的词汇掌握清单。在「我的 → 长期记忆」查看和编辑正文；文档保存在本地存储，并非仓库中的实际 `MEMORY.md` 文件。

阅读页的「文章答疑」使用当前章节作为上下文。学习页的「随时问」使用当前对话中可见的题目、回答和 AI 解析作为上下文，不改变课程进度、不写入长期记忆，关闭后丢弃临时对话。两者使用共用悬浮聊天组件。

## 开发与构建

需要 Node.js、npm 和微信开发者工具。

```sh
npm ci
npm run check
```

在微信开发者工具中打开仓库根目录。`project.config.json` 的 `miniprogramRoot` 指向 `dist/`。修改源码后执行 `npm run build`，不要编辑 `dist/` 中的生成文件。

```sh
npm run typecheck         # TypeScript 严格类型检查
npm test                 # 回归测试，不调用真实 AI 服务
npm run build            # 编译并复制模板、样式和资源到 dist/
npm run check            # 类型检查、测试、构建
npm run verify:templates # 使用本机微信编译器检查 WXML / WXSS
```

`verify:templates` 默认使用 Windows 微信开发者工具安装目录下的编译器；其他安装位置可通过环境变量 `WECHAT_COMPILER_DIR` 指定包含 `wcc.exe` 和 `wcsc.exe` 的目录。自动化检查不能替代真机上的键盘、手势、滚动和网络验证。

## AI 配置

在「我的 → 系统设置」填写一个**阿里云百炼 API Key**，保存后可测试连接与模型响应。接口、模型名称和朗读服务由代码内置，用户不能修改。

当前代码配置：

| 用途 | 配置 |
| --- | --- |
| 对话接口 | `https://dashscope.aliyuncs.com/compatible-mode/v1` |
| 主模型 | `deepseek-v4-flash` |
| 辅助模型 | `qwen-flash` |
| 朗读模型 | `qwen3-tts-flash` |

配置见 `services/storage.ts`，朗读实现见 `services/audio.ts`。以上是项目内置值，实际调用取决于账户权限和服务端支持。

小程序后台需配置请求合法域名，其中百炼请求使用 `https://dashscope.aliyuncs.com`。词典、音频下载等其他域名以设置页「复制域名」和实际服务返回地址为准。

源码不包含默认 API Key，勿将真实密钥提交到 Git。Key 和学习数据目前保存在本地，尚未接入云服务。本地兜底开关控制网络失败时是否使用内置词库和已有句译。

## 项目结构

| 目录 | 职责 |
| --- | --- |
| `core/` | 数据模型、分词、阅读流、学习规则、记忆上下文、流式和 Markdown 解析 |
| `services/` | 学习业务、存储、AI 请求、词典、音频、主题与字体 |
| `pages/` | 书架、阅读、学习、设置、长期记忆等页面 |
| `components/` | 试卷、阅读文本、选词文本、悬浮问答、自定义弹窗与图标 |
| `custom-tab-bar/` | 底部导航 |
| `data/` | 内置文章与离线词库 |
| `tests/` | 学习流程、分页存储、中断恢复、网络及文本交互等回归测试 |
| `tools/` | 构建、模板验证及开发辅助脚本 |
| `docs/` | 功能和架构记录；历史文档可能描述已替换的方案 |

### 学习模块

`services/learning.ts` 是页面调用的公开入口，内部按职责拆分：

| 模块 | 职责 |
| --- | --- |
| `learning-repository.ts` | 对话目录、课程状态、消息分页、长期记忆和版本检查 |
| `learning-runtime.ts` | 同课操作互斥、上下文组装、结构化请求和消息追加 |
| `learning-generation.ts` | 分步生成文章和试卷、发布章节、闯关后解锁 |
| `learning-conversation.ts` | 水平测评、作答讲解和错题复测 |
| `learning-exam.ts` | 提交快照、整卷批改和空答处理 |
| `learning-archive.ts` | 归档总结、记忆合并及失败重试 |
| `learning-aside.ts` | 不写入学习记录的临时随时问 |
| `learning-prompts.ts` | 学习流程提示词 |

阶段转换和试卷计划集中在 `core/learning-flow.ts`。模型负责内容生成和批改，程序负责流程推进、完成条件与提交锁定。

## 本地数据与可靠性

学习数据分开保存为 `learning_v2_index`、`learning_v2_session_<id>`、`learning_v2_messages_<id>_<page>` 和 `learning_v2_memory`。消息每页最多 20 条，页面按需读取；追加时仅写入变化的消息页，避免反复读写全部课程历史。

`services/local-storage.ts` 提供多键写入与恢复记录。写入失败或完成前退出时，下次读取先尝试回滚，避免章节与课程进度只保存一半。它依赖本地存储可用，不等同于数据库事务或云备份。

「清理缓存」保留书籍、笔记和学习记录；清除全部用户数据会删除对话与长期记忆。导出和恢复备份目前没有用户界面入口，云存储尚未实现。

当前代码仍有旧数据迁移及内部备份兼容路径，但测试阶段不将旧数据兼容作为后续开发约束。存储结构调整时可以重置测试数据；正常作答保存、重复提交防护及中断恢复仍属于必测功能。

本轮整理详见 [学习架构设计](docs/superpowers/specs/2026-09-28-learning-architecture-design.md)。
